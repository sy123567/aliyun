# 06 - 基于 Agentic AI 的卡车司机连续找货决策设计过程思路总文档

## 1. 文档目标

本文档面向“基于 Agentic AI 的卡车司机连续找货决策”实验与竞赛任务，说明从数据理解、问题建模、智能体架构、算法选择、决策流程、偏好约束处理到本地验证的总体设计过程。

本方案的核心目标不是预测单笔订单是否值得接，而是在完整月度仿真周期内持续决策，使司机在“接单、休息、空驶”三类动作之间做出兼顾短期收益、长期机会和个性化偏好的选择。

**核心约束强调**：
- 仅允许修改 `demo/agent/` 目录下代码
- 禁止读取任何外部数据文件（含 `cargo_dataset.jsonl`、`drivers.json`）
- **必须通过大模型动态解析偏好，严禁硬编码规则**（评委重点核查项）
- 禁止离线优化，所有决策必须在线实时完成

### 2.2 数据概况

实验数据位于 `demo/server/data/`：

- **货源数据**：`cargo_dataset.jsonl`，约 50 万条 JSONL 货源记录。
- **司机数据**：`drivers.json`，公开样例中包含 10 位司机。

货源常用字段包括：

- **`cargo_id`**：货源唯一编号。
- **`create_time` / `remove_time`**：货源上架与失效时间。
- **`cargo_name`**：货源品类。
- **`start` / `end`**：装货点与卸货点坐标及城市信息。
- **`load_time`**：装货时间窗。
- **`cost_time_minutes`**：订单运输耗时。
- **`price`**：货源价格，原始数据以分为单位；通过接口返回时已转换为元。
- **`truck_length`**：可承运车型长度要求。

司机常用字段包括：

- **`driver_id`**：司机 ID。
- **`truck_length`**：车辆长度。
- **`cost_per_km`**：单位里程成本。
- **`current_lat` / `current_lng`**：当前位置。
- **`preferences`**：个性化偏好文本与罚分信息。

```text
│  ✅ 使用历史决策数据进行在线学习和预测                          │
│  ✅ 在 Agent 目录内新增辅助模块                                │
└─────────────────────────────────────────────────────────────────┘
```

参赛 Agent 在仿真运行中不得直接读取 `cargo_dataset.jsonl` 和 `drivers.json`。决策时只能通过赛方提供的接口获取信息：

- **`get_driver_status(driver_id)`**：获取当前司机状态、位置、仿真时间、可见偏好等。
- **`query_cargo(driver_id, latitude, longitude)`**：查询指定位置附近当前可见货源。
- **`query_decision_history(driver_id, step)`**：查询本次仿真会话中的历史动作。
- **`model_chat_completion(payload)`**：调用统一模型网关，复赛基座模型为 `qwen3.5-flash`。

因此，算法设计必须遵循“运行时不直读全量数据、只基于接口可观测信息决策”的原则。

## 3. 问题建模

该任务可抽象为带软约束的有限时域序贯决策问题，接近部分可观测马尔可夫决策过程。

### 3.1 状态

每一步可观测状态包括：

- **时间状态**：`simulation_progress_minutes`、墙钟时间、剩余仿真时长。
- **空间状态**：司机当前位置，经纬度。
- **司机状态**：车型、已完成订单数、历史动作。
- **货源状态**：当前位置或指定位置附近的在架货源候选。
- **偏好状态**：当前可见的个性化规则文本。

### 3.2 动作

每轮只能输出一种动作：

- **接单**：`{"action":"take_order","params":{"cargo_id":"..."}}`
- **休息**：`{"action":"wait","params":{"duration_minutes":正整数}}`
- **空驶**：`{"action":"reposition","params":{"latitude":...,"longitude":...}}`

### 3.3 状态转移

环境采用事件驱动推进：

- 接单会推进到订单完成后的时间与地点。
- 休息会推进指定分钟数，位置不变。
- 空驶会根据 Haversine 距离和配置速度推进时间并更新位置。
- 查询货源会产生浏览时间成本，Demo 默认每 10 条货源消耗 1 分钟。

### 3.4 优化目标

评分目标可理解为最大化月度综合收益：

```text
net_income = gross_income - distance_km * cost_per_km - preference_penalty
```

其中：

- **`gross_income`**：成功接单收入。
- **`distance_km * cost_per_km`**：空驶和干线行驶成本。
- **`preference_penalty`**：违反司机偏好的罚分。

因此，本任务不能只看单笔价格，而要同时考虑接单后的时间占用、位置变化、空驶成本、未来货源机会和偏好罚分。

### 3.5 动态偏好状态

偏好可能随时间变化（如家庭事务、货源波动等因素），因此需要：

```text
preference_state = {
    "current_rules": {},           # 当前生效的规则
    "last_parse_time": 0,          # 上次解析时间戳
    "parse_failure_count": 0,      # 解析失败次数
    "dynamic_changes": []          # 偏好变更历史记录
}
```

## 4. 推荐算法标注

### 4.1 主算法

本实验推荐采用：

> **动态偏好感知的在线滚动时域多目标评分算法**  
> Dynamic Preference-aware Online Rolling Horizon Multi-objective Scoring，简称 **DP-ORH-MS**。

核心改进：
- **实时偏好解析**：每步检查偏好文本是否变化，动态更新规则
- **在线学习机制**：从历史决策中学习区域价值、时间模式等
- **自适应评分权重**：根据当前状态动态调整各评分维度权重
- **风险控制**：针对预测误差设置风险补偿机制

选择该算法的原因：

- **适配接口约束**：每步只能看到接口返回的局部候选货源，难以使用需要全量状态的传统动态规划。
- **可解释性强**：每个动作分数可拆解为收入、成本、时间、偏好和未来机会，便于调试。
- **响应稳定**：比每步完全依赖大模型自由推理更稳定，能降低 JSON 格式错误和超时风险。
- **易于接入大模型**：大模型负责偏好解析、复杂规则理解和少量难例裁决，确定性打分器负责主决策。
- **适合月度连续经营**：用滚动时域估计接单后的目的地价值和休息/空驶后的机会，而不是孤立选择最高单价订单。
- **动态偏好适应**：支持偏好文本的动态变化，无需重新部署即可适应新规则。

### 4.2 辅助算法

方案中配套使用以下算法或方法：

- **Haversine 大圆距离算法**：计算空驶距离、赴装货点距离、干线距离、空间约束距离。
- **规则约束过滤算法**：过滤车型不匹配、时间窗失效、禁运品类、禁入区域、夜间禁行等不合规动作。
- **多目标加权评分算法**：综合订单收入、距离成本、时间成本、装货等待、偏好罚分和未来机会。
- **滚动时域 Model Predictive Control 思路**：每一步基于当前状态向前估计 1 到 2 步价值，执行当前最优动作，下一轮重新评估。
- **在线热点记忆与聚类思想**：从历史可见货源的装货点、卸货点、成交后位置中维护高机会区域，不直接读取全量货源数据。
- **LLM 结构化偏好解析**：使用 `qwen3.5-flash` 将自然语言偏好解析为可执行约束与软惩罚项。
- **自适应权重调整**：根据当前状态动态调整评分维度权重。

## 5. 智能体总体架构

推荐智能体由以下模块组成：

```text

  ├─ 在线热点记忆（网格聚合）
  └─ 偏好变更记录（检测动态变化）

  ├─ LLM 实时解析偏好文本

  ├─ 接单候选（过滤后保留Top 30-50）
```

## 6. 决策流程设计

### 6.1 单步决策流程（强化动态偏好处理）

每次 `decide(driver_id)` 的流程如下：

1. **读取当前司机状态**  
   调用 `get_driver_status(driver_id)`，获取当前位置、仿真时间、车型、已完成订单数和当前可见偏好。

2. **检测偏好变化**  
   对比当前偏好文本与历史记录，判断是否需要重新解析。

3. **动态解析偏好（如变化或首次）**  
   调用 LLM 解析偏好文本为结构化规则，并缓存结果。

4. **读取历史动作**  
   调用 `query_decision_history(driver_id, step)`，建议读取最近若干步，用于判断连续休息、夜间动作、当日接单次数、是否已回家等。

5. **查询当前位置附近货源**  
   调用 `query_cargo(driver_id, current_lat, current_lng)`，获得当前位置附近当前在架货源。注意查询本身会消耗仿真时间，因此不能无限制多点查询。

6. **更新在线记忆**  
   更新热点区域、价格模式、时间分布等在线学习数据。

7. **生成候选动作**  
   基于货源、时间、位置和偏好生成接单、休息、空驶候选。

8. **合法性过滤**  
   排除明显不可执行或高违规风险动作。

9. **多目标自适应评分**  
   对候选动作计算综合效用，根据当前状态动态调整权重。

10. **输出动作 JSON**  
    选择分数最高的动作，并保证输出符合接口要求，记录决策理由便于复核。

### 6.2 伪代码（优化版）

```text
decide(driver_id):
    status = get_driver_status(driver_id)
    
    # 关键：检测偏好变化
    if status.preferences != self._last_preferences.get(driver_id):
        rules = parse_preferences_dynamically(status.preferences)
        self._last_preferences[driver_id] = status.preferences
        self._preference_rules[driver_id] = rules
    else:
        rules = self._preference_rules.get(driver_id, {})
    
    history = query_decision_history(driver_id, 20)
    cargo_items = query_cargo(driver_id, status.current_lat, status.current_lng)
    
    # 更新在线记忆（增量式）
    update_online_memory(driver_id, cargo_items, history)
    
    # 生成候选动作
    order_candidates = build_order_candidates(cargo_items, status, rules)
    wait_candidates = build_wait_candidates(status, history, rules)
    reposition_candidates = build_reposition_candidates(status, cargo_items, rules)
    
    # 合法性过滤
    feasible = filter_by_hard_constraints(order_candidates + wait_candidates + reposition_candidates)
    
    if not feasible:
        return safe_wait_action(status, rules)  # 兜底动作
    
    # 自适应评分（根据当前状态调整权重）
    scored = adaptive_multi_objective_scoring(feasible, status, rules)
    best = argmax(scored.score)
    
    # 记录决策理由（便于人工复核）
    record_decision_reason(driver_id, best, scored)
    
    return best.to_action_json()
```

## 7. 候选动作生成策略

### 7.1 接单候选

对 `query_cargo` 返回的货源生成接单候选。建议保留前 30 到 50 条进行详细评分，而不是简单只看最近 20 条。

每个接单候选需要计算：

- **赴装货点空驶距离**：当前点到 `start` 的 Haversine 距离。
- **赴装货点时间**：按配置速度换算，Demo 示例为 60 km/h。
- **装货时间窗等待**：如果早到，需要等待到 `load_time` 开始。
- **是否错过时间窗**：如果到达晚于 `load_time` 结束，过滤。
- **干线距离**：`start` 到 `end` 的 Haversine 距离。
- **运输耗时**：`cost_time_minutes`。
- **预计完成时刻和完成位置**：用于未来机会评估。
- **车型匹配**：司机 `truck_length` 应在货源 `truck_length` 范围内。
- **品类偏好**：如果偏好禁止某些 `cargo_name`，则过滤或重罚。
- **月末约束**：预估完单时刻是否会超过当月仿真上界。

### 7.2 休息候选（强化偏好驱动）

休息不是简单兜底动作，而是满足偏好与等待市场机会的重要动作。

```text
休息候选生成策略：
├─ 偏好驱动休息
│  ├─ 每日连续休息要求（3/4/5/8小时）
│  └─ 月度休息日要求
├─ 时间窗驱动休息
│  ├─ 夜间禁行时段（如22:00-06:00）
│  └─ 午餐时段禁行
├─ 市场驱动休息
│  ├─ 货源低谷时段（凌晨1-4点）
│  └─ 等待新货源上架（30/60分钟）
└─ 紧急休息
   └─ 疲劳驾驶预警（累计驾驶时长阈值）
```

### 7.3 空驶候选（强化在线热点）

空驶会产生成本和时间，因此只在当前货源稀缺或目的地机会显著更高时使用。

```text
空驶候选优先级：
1. 偏好目标点（回家点、必须到达点）
2. 高价值货源装货点（价格/时间比高）
3. 在线热点区域（网格聚合高密区）
4. 历史高收益卸货点（学习记忆）
5. 区域边界内安全点位

约束：
├─ 空驶距离不超过偏好阈值
├─ 目标点必须在许可区域内
└─ 避免进入禁入区域
```

不建议大量多点试探查询，因为每次 `query_cargo` 都会消耗仿真时间。

## 8. 多目标评分函数设计

### 8.1 接单评分

接单候选的建议评分公式：

```text
score_order = income
              - distance_cost
              - time_cost
              - pickup_deadhead_penalty
              - waiting_penalty
              - preference_risk_penalty
              - horizon_risk_penalty
              + future_location_value
```

各项含义：

- **`income`**：货源价格，接口返回口径为元。
- **`distance_cost`**：`cost_per_km * (pickup_deadhead_km + haul_km)`。
- **`time_cost`**：单位时间机会成本，可按当前平均每小时收益动态估计。
- **`pickup_deadhead_penalty`**：额外惩罚接单前空驶距离，避免远距离抢单。
- **`waiting_penalty`**：装货时间窗导致的等待成本。
- **`preference_risk_penalty`**：违反偏好或接近违规边界的预估罚分。
- **`horizon_risk_penalty`**：月底无法完成订单或超出仿真周期的风险。
- **`future_location_value`**：预计卸货地在完成时刻附近的未来机会价值。

### 8.2 休息评分

休息候选的建议评分公式：

```text
score_wait = rest_preference_gain
             + low_market_avoid_gain
             + no_drive_window_avoid_gain
             - opportunity_loss
```

适合休息的情况：

- 当前无可接高分货源。
- 当前处于司机偏好的禁行/禁接时间段。
- 当日尚未满足连续休息要求。
- 继续接单可能导致夜间无法回家或违反家庭事务约束。
- 低谷时段短暂等待可看到更多货源。

### 8.3 空驶评分

空驶候选的建议评分公式：

```text
score_reposition = expected_market_gain
                   + preference_target_gain
                   - reposition_cost
                   - reposition_time_cost
                   - preference_risk_penalty
```

只有在以下条件下才建议空驶：

- 当前附近货源少或收益明显偏低。
- 目标区域在历史观测中货源密度或订单收益更高。
- 目标点能同时满足回家、到达指定点、避开禁区等偏好。
- 空驶距离不超过司机偏好或经济合理阈值。

### 8.4 自适应权重机制

根据当前状态动态调整评分权重：

```text
权重调整策略：
├─ 月末阶段（剩余<3天）
│  ├─ horizon_risk_weight × 2
│  └─ future_value_weight × 0.5
├─ 偏好即将违规
│  └─ preference_risk_weight × 3
├─ 货源稀缺（<5条）
│  ├─ pickup_deadhead_weight × 0.5
│  └─ reposition_gain_weight × 1.5
└─ 夜间时段
   └─ time_cost_weight × 0.3
```

## 9. 个性化偏好处理（重点强化）

### 9.1 动态偏好解析机制

**核心要求**：必须通过大模型动态解析，**严禁硬编码**任何司机规则。

```text
偏好解析流程：
1. 获取当前偏好文本（status.preferences）
2. 对比历史记录检测变化
3. 调用 Qwen3.5-Flash 解析为结构化规则
4. 验证规则完整性
5. 缓存解析结果（按偏好文本哈希）
6. 记录解析时间和版本

解析失败处理：
├─ 使用保守默认规则
├─ 增加偏好风险惩罚
└─ 记录日志便于调试
```

推荐使用 `qwen3.5-flash` 将偏好文本解析成结构化规则，解析结果缓存在司机维度，避免每步重复调用模型。

### 9.2 不硬编码司机 ID

虽然公开样例中能看到 D001 到 D010 的偏好，但正式评测会更换司机和数据，因此不应写 `if driver_id == "D009"` 这类硬编码规则。

正确做法是：

- 基于接口返回的 `preferences` 文本解析规则。
- 对相同语义规则实现通用校验。
- 对解析失败的偏好设置较保守的风险惩罚。
- 将偏好原文和解析结果写入日志，便于调试。

### 9.3 常见偏好类型

公开样例中出现的偏好可归纳为：

- **休息类**：每天连续停车休息 3、4、5、8 小时。
- **禁行时间类**：夜间或午餐时段不接单、不空驶。
- **品类禁运类**：不接某些货源品类。
- **距离限制类**：单笔干线距离或赴装货点空驶距离不得超过阈值。
- **区域限制类**：不得离开某城市范围，不得进入指定禁区。
- **月度休息类**：自然月内至少 N 天完全不出车。
- **回家类**：每天指定时间前回到家附近并停留。
- **特殊任务类**：指定日期到达某点、接人、回家并静止若干天。
- **熟货源类**：指定货源编号需要优先关注。

## 10. 未来机会估计

因为智能体不能读取全量货源库，只能通过接口观察局部货源，所以未来机会估计应采用在线方式。

### 10.1 在线记忆机制（增量式）

```text
在线记忆结构：
├─ 区域热点统计（网格聚合）
│  ├─ 货源密度
│  ├─ 平均价格
│  ├─ 接单成功率
│  └─ 后续货源丰富度
├─ 时间模式学习
│  ├─ 每日货源高峰期
│  ├─ 每周波动模式
│  └─ 天气/节假日影响
└─ 偏好满足记录
   ├─ 已满足偏好
   ├─ 即将到期偏好
   └─ 偏好违规历史
```

在每一步中记录：

- 查询到的货源装货点分布。
- 货源价格、品类、距离、运输时长。
- 接单后的卸货位置。
- 该区域后续是否容易继续接到高收益货源。
- 空驶到某区域后的收益表现。

### 10.2 热点价值

将经纬度划分为网格或使用简单聚类，维护每个区域的统计值：

```text
area_value = avg_price_per_hour
             + cargo_density_bonus
             - avg_deadhead_penalty
             - preference_risk
```

用于估计：

- 接某单后到达的卸货地是否值得。
- 当前无好单时是否空驶到某热点。
- 是否应该等待而不是跨区域移动。

### 10.3 滚动时域

每一步只执行当前动作，但评分时向前估计 1 到 2 步：

- 接单：估计完成后目的地价值。
- 空驶：估计到目标点后可见货源价值。
- 休息：估计休息后是否进入更好的时间窗口或满足偏好。

下一轮环境状态更新后重新计算，这就是滚动时域控制思想。

### 10.4 预测误差风险控制

根据官方提示“允许使用历史数据做预测，但风险自担”，增加风险控制：

```text
风险控制策略：
├─ 预测置信度评估
│  └─ 对低置信度预测增加惩罚
├─ 多样化策略
│  └─ 避免过度依赖单一预测
├─ 回退机制
│  └─ 预测失败时使用保守策略
└─ 自适应学习率
   └─ 根据预测误差动态调整
```

## 11. 大模型使用策略

### 11.1 大模型职责（明确边界）

```text
LLM 职责边界：
├─ ✅ 偏好文本结构化解析（核心）
├─ ✅ 复杂偏好冲突解释
├─ ✅ 少量候选动作的语义裁决
├─ ✅ 输出 JSON 格式校验或修复
└─ ❌ 数值计算和评分（由确定性代码完成）
```

大模型不建议直接承担全部数值决策，而应承担以下职责：

- **偏好文本结构化解析**。
- **复杂偏好冲突解释**。
- **少量候选动作的语义裁决**。
- **输出 JSON 动作格式校验或修复**。

### 11.2 Token 消耗控制（针对4小时仿真）

```text
Token 控制策略：
├─ 偏好解析缓存（相同文本不重复解析）
├─ 每步候选货源限制（≤30条传给模型）
├─ 结构化摘要输入（避免完整列表）
├─ Token 预算监控（每司机≤500万）
└─ 降级机制（超预算时切换纯规则模式）
```

为满足响应耗时和 token 限制：

- 同一司机偏好解析结果应缓存。
- 每步传给模型的候选货源不宜过多，可先由规则评分选出 Top N。
- 常规数值评分用 Python 规则完成。
- 模型只处理结构化摘要，而不是完整货源列表。
- 模型异常时必须有确定性兜底动作，例如短休息或选择最高分安全订单。

### 11.3 Prompt 设计要点

模型提示词应强调：

- 只能输出 JSON 对象。
- 只能选择 `take_order`、`wait`、`reposition`。
- 不得输出解释、Markdown 或额外文本。
- 若存在偏好冲突，优先避免高额罚分和非法动作。
- 必须考虑时间窗、剩余仿真时长、车型、品类和空间约束。

## 14. 风险点与处理策略（强化版）

### 14.1 价格单位风险

原始货源价格以分为单位，但 `query_cargo` 返回时已被转换为元。评分时应基于接口返回值，不要重复除以 100。

### 14.2 查询货源会推进时间

每次 `query_cargo` 根据返回条数产生浏览耗时。过度多点查询会消耗司机可运营时间，降低收益。

### 14.3 时间窗风险

接单前必须估算到达装货点时间：

- 到达晚于 `load_time` 结束，应过滤。
- 到达早于 `load_time` 开始，应计入等待成本。
- 月末超出仿真上界的订单应重罚或过滤。

### 14.4 偏好罚分风险

偏好可能带来远高于单笔订单收益的罚分。策略应优先避免：

- 高额一次性罚分。
- 上不封顶的分钟级罚分。
- 禁入区域和特殊家庭任务。
- 熟货源指定任务未完成。

### 14.5 过度依赖大模型风险

模型可能输出格式错误或忽略细节。应通过确定性代码完成主评分和动作校验，模型输出只作为可控输入。

### 14.6 Token 超预算风险

实施预算监控，超过阈值时降级为纯规则模式。

### 14.7 离线优化检测风险

严格遵守规则，禁止读取任何外部数据文件，所有决策必须在线实时完成。

| 风险点 | 处理策略 |
|-------|---------|
| **偏好解析失败** | 使用保守默认规则 + 增加风险惩罚 + 记录日志 |
| **Token 超预算** | 实施预算监控 + 降级为纯规则模式 + 优先缓存 |
| **仿真时间耗尽** | 月末前减少空驶 + 优先短订单 + 预留完成时间 |
| **预测误差** | 置信度评估 + 风险补偿 + 多样化策略 |
| **硬编码检测** | 代码审查 + 随机测试司机 + 禁止 driver_id 判断 |
| **离线优化检测** | 禁止文件读取 + 仅允许API调用 + 时间戳验证 |

## 15. 方案总结

本实验建议采用 **DP-ORH-MS：动态偏好感知的在线滚动时域多目标评分算法** 作为主算法，并结合 `qwen3.5-flash` 完成 Agentic AI 的工具调用、偏好解析和复杂语义判断。

**核心优势**：
- ✅ 严格遵守赛事规则（禁止硬编码、禁止离线优化）
- ✅ 动态偏好解析（LLM实时解析，适应变化）
- ✅ 在线学习机制（增量式热点记忆、时间模式）
- ✅ 自适应评分（根据状态动态调整权重）
- ✅ 风险控制（预测误差、Token预算、异常兜底）
- ✅ 可调试性（完整日志记录，便于人工复核）

最终智能体应具备以下特点：

- **遵守接口约束**：运行时不直读原始数据，只通过环境 API 查询状态和货源。
- **收益导向**：以月度净收益为目标，而不是单笔订单价格最大化。
- **偏好感知**：将司机偏好转为可执行约束和罚分估计，支持动态变化。
- **滚动决策**：每轮基于最新状态重新评分，兼顾当前动作和后续机会。
- **工程稳健**：输出 JSON 可校验，有日志、有兜底、有异常处理。

推荐在提交作品中说明采用算法为：

```text
主算法：动态偏好感知的在线滚动时域多目标评分算法（DP-ORH-MS）
辅助方法：LLM实时偏好解析、Haversine距离计算、规则约束过滤、在线热点记忆、自适应多目标评分、风险控制机制
基座模型：Qwen3.5-Flash
代码位置：demo/agent/ 目录下所有文件
```
