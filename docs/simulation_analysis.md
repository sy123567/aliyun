### V4e核心改动

**罚金感知休息日调度** (`scoring.py` `build_wait_durations()`):

原始逻辑仅在 `cur_md <= 90`（凌晨1:30前）生成全天等待候选，导致高罚金司机（如D002）错过休息日安排。

V4e改进：当天尚未接单(`not today_already_active`)且有休息日缺口(`days_off_deficit > 0`)时，生成全天等待候选。**关键约束**：仅当 `penalty_amount >= 4000` 元时适用。

**阈值选择理由**：
- D002: penalty_amount=6000 >= 4000 -> 适用（V3罚金6,000，V4e罚金200，净收入+3,216）
- D006: penalty_amount=3000 < 4000 -> 不适用（防止过度休息导致净收入下降）
- D007: penalty_amount=800 < 4000 -> 不适用
- D008: penalty_amount=750 < 4000 -> 不适用

### V3优化策略（保留）

1. **智能LLM门控**：三重过滤减少95%无效LLM调用
   - 门控1: 评分差距>5x时跳过LLM
   - 门控2: 前两名动作类型相同时跳过（LLM无法区分wait-120 vs wait-60）
   - 门控3: 绝对分差<50元时跳过
   - 效果: LLM调用从1,231次->63次，0次覆盖评分系统决策

2. **休息日配速增强**：提高月度休息日调度的积极性
   - 降低urgency阈值: 0.1->0.03（捕获1天休息需求的司机）
   - 提高最低配速系数: urgency->max(0.4, urgency)*1.5
   - 提高主动休息增益: base*0.4->base*0.6

### 进一步优化方向

达到30w(300,000)目标的差距约52,160元：

1. **减少罚金** (潜力~17,090)：
   - D006月休日(3,000): penalty_amount不够高，强制休息会损失更多收入
   - D004午休(3,500): 软约束，硬拒会损失更多收入(100元罚金 vs ~156元机会成本)
   - D009夜间(2,700): 需改善回家路线规划
   - D008月休日+日休(2,600): penalty_amount=750，强制休息不划算

2. **提高毛收入** (需额外~35,000+)：
   - 更优的接单策略（选择更高价值订单）
   - 减少空驶里程比例
   - 优化等待策略（减少不必要的长等待）
   - 更大规模参数搜索（50-100轮Optuna trial）
   - LLM战略规划（预判货源热点区域、多日路线优化）
